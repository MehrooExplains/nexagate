NexaGate یک پروژهٔ اولیه برای سرور لینوکسی است که پنج ورودی مقاوم در برابر فیلترینگ را به دو مسیر خروجی جدا وصل می‌کند:

- ترافیک داخلی **TCP** از شبکهٔ **Psiphon** خارج می‌شود؛
- ترافیک داخلی **UDP** و DNS تونل از **Cloudflare WARP** خارج می‌شود؛
- فایروال fail-closed اجازه نمی‌دهد Xray، Hysteria یا DNS در زمان قطعی به اینترنت مستقیم سرور برگردند.

> وضعیت پروژه: نسخهٔ `0.2.0`. پیش از استفادهٔ عملی، آن را روی یک سرور تازه و قابل‌بازیابی آزمایش کنید. هیچ پروتکل یا سروری نمی‌تواند عبور از تمام روش‌های فیلترینگ را تضمین کند.

## معماری پروژه

```text
کاربرها
  ├─ UDP/443  ─ Hysteria2
  ├─ TCP/443  ─ VLESS + XHTTP + REALITY
  ├─ TCP/8444 ─ VLESS + RAW + REALITY + Vision
  └─ TCP/2053 ─ Nginx TLS/HTTP2
                    ├─ VLESS + XHTTP + TLS
                    └─ VLESS + WebSocket + TLS
                         │
                  جداسازی TCP و UDP
                     /           \
          TCP → Psiphon       UDP → WARP (warp0)
                    DNS → رلهٔ محلی → WARP

مدیریت: TCP/8443 → Nginx HTTPS → پنل روی 127.0.0.1:9080
```

### ورودی‌ها و پورت‌ها

| پورت عمومی | پروتکل | کاربرد |
|---|---|---|
| UDP `443` | Hysteria2 + Salamander | پروفایل اصلی و سریع مبتنی بر UDP |
| TCP `443` | VLESS + XHTTP + REALITY | پروفایل مقاوم با ظاهر نزدیک به HTTPS |
| TCP `8444` | VLESS + RAW + REALITY + Vision | پروفایل سازگار REALITY |
| TCP `2053` | VLESS + XHTTP + TLS روی HTTP/2 | مسیر پشتیبان HTTPS واقعی هنگام اختلال REALITY یا UDP |
| TCP `2053` | VLESS + WebSocket + TLS | مسیر قدیمی اضطراری با آدرس مخفی جداگانه |
| TCP `8443` | HTTPS | پنل مدیریت |
| TCP `80` | فقط HTTP-01 | صدور و تمدید گواهی Let's Encrypt |

استفادهٔ هم‌زمان TCP و UDP از پورت `443` مشکلی ندارد، چون دو نوع انتقال متفاوت هستند.

## امکانات اصلی

- دو حالت کاملاً مستقل فارسی راست‌به‌چپ و انگلیسی چپ‌به‌راست با ذخیرهٔ انتخاب زبان و سایدبار واکنش‌گرا؛ نوشته‌های دو زبان در یک صفحه با هم ترکیب نمی‌شوند
- صفحه‌های مستقل نمای کلی، کاربران، ورودی‌ها، خروجی‌ها، مسیریابی و تنظیمات پنل
- نمایش زندهٔ CPU، رم، Swap، فضای دیسک، سرعت و مجموع ترافیک، سوکت‌ها، Load Average، آپ‌تایم و مصرف خود پنل
- فونت‌های داخلی Inter و Vazirmatn UI همراه با اعداد هم‌عرض JetBrains Mono؛ بدون وابستگی پنل به CDN فونت
- آیکن‌های SVG داخلی Lucide با اندازهٔ یکسان ۲۰ پیکسل در منو؛ بدون وابستگی پنل به CDN آیکن
- محوشدن آدرس‌های IP سرور به‌صورت پیش‌فرض و نمایش آن‌ها فقط با دکمهٔ چشم
- به‌روزرسانی یک‌کلیکی پنل همراه با بررسی checksum، تست سلامت و بازگشت خودکار به نسخهٔ قبل
- جست‌وجو، ساخت، غیرفعال‌کردن، تاریخ انقضا و حذف کاربر در صفحهٔ اختصاصی مدیریت حساب‌ها
- پنج لینک اتصال و QR Code برای هر کاربر، شامل مسیر پشتیبان XHTTP با TLS واقعی
- مهاجرت خودکار و سازگار کانفیگ قدیمی هنگام اضافه‌شدن تنظیمات جدید در آپدیت یک‌کلیکی
- انتخاب خودکار سرور سایفون یا تعیین کشور با کد دوحرفی مانند `DE`
- انتخاب خودکار endpoint وارپ با سنجش پینگ و سرعت
- پروفایل و فضای شبکهٔ جدا برای تست WARP تا کاربران فعال قطع نشوند
- رلهٔ DNS که سوکت خروجی آن به `warp0` قفل شده است
- kill-switch مبتنی بر کاربر سرویس در nftables برای Xray، Hysteria و DNS
- SOCKS سایفون و هستهٔ پنل فقط روی localhost
- سرویس‌های systemd محدودشده و بدون دسترسی root
- نوشتن اتمیک کانفیگ و اعتبارسنجی پیش از اعمال تغییر
- بررسی خودکار سلامت سایفون
- گرفتن گواهی دامنه یا IP عمومی با [CertDuo](https://github.com/MehrooExplains/certduo)
- بررسی پیش‌نیازها و نصب فقط مواردی که روی سرور وجود ندارند
- کنترل SHA-256 همهٔ فایل‌ها و باینری‌های دانلودی پین‌شده

## سیستم‌های پشتیبانی‌شده

نسخهٔ اول برای شرایط زیر آماده شده است:

- سرور تازهٔ لینوکسی مبتنی بر systemd؛
- معماری `amd64` یا `x86_64`؛
- یکی از مدیرهای بستهٔ `apt`، `dnf` یا `yum`؛
- IPv4 عمومی؛
- دسترسی root یا `sudo`.

محدودیت معماری به‌خاطر باینری رسمی لینوکسی سایفون است که در این نسخه فقط برای x86_64 استفاده می‌شود. بیشترین آزمایش روی Debian/Ubuntu انجام شده و موجودبودن بسته‌ها در توزیع‌های خانوادهٔ RHEL ممکن است به مخزنهای فعال بستگی داشته باشد.

### پورت‌های لازم

این پورت‌ها را هم در فایروال سرور و هم در Security Group شرکت میزبان باز کنید:

```text
TCP: 80, 443, 2053, 8443, 8444
UDP: 443
```

برای گواهی دامنه، قبل از نصب یک رکورد `A` بسازید که مستقیماً به IP همین سرور اشاره کند. پورت `80` باید برای HTTP-01 از اینترنت در دسترس باشد. هنگام صدور اولیه، CDN یا HTTP Proxy نباید درخواست challenge را تغییر دهد.

## نصب

با حسابی که دسترسی root یا `sudo` دارد، نصب تعاملی را با یک دستور اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/MehrooExplains/nexagate/main/install.sh)
```

اسکریپت تک‌فایلی در صورت نیاز خودکار از `sudo` استفاده می‌کند، نسخهٔ کامل پروژه را از همین مخزن می‌گیرد، پیش‌نیازها را بررسی می‌کند، فقط مواردی را که موجود نیستند نصب می‌کند و سپس نصب تعاملی را ادامه می‌دهد. برای بررسی کد پیش از اجرا، فایل [install.sh](install.sh) را باز کنید؛ روش clone کردن مخزن و اجرای `sudo ./install.sh` نیز همچنان پشتیبانی می‌شود.

نصب‌کننده این موارد را سؤال می‌کند:

1. نوع گواهی: دامنه یا IP عمومی همین سرور؛
2. ایمیل حساب Let's Encrypt؛
3. نام دامنه در صورت انتخاب گزینهٔ اول؛
4. رمز مدیر پنل؛
5. مقصد ظاهری REALITY که اختیاری است.

سپس این مراحل انجام می‌شود:

1. بررسی Linux، systemd، معماری x86_64، پورت‌های آزاد و مدیر بسته؛
2. بررسی تک‌تک پیش‌نیازها و نصب فقط مواردی که موجود نیستند؛
3. راه‌اندازی Nginx حداقلی برای مسیر HTTP-01؛
4. دانلود نسخهٔ پین‌شدهٔ CertDuo و کنترل checksum؛
5. گرفتن گواهی دامنه یا گواهی کوتاه‌عمر IP عمومی به‌وسیلهٔ CertDuo؛
6. دانلود و اعتبارسنجی Xray، Hysteria2، wgcf، سایفون و در صورت نیاز Go موقت؛
7. build و اجرای تست‌های NexaGate روی همان سرور؛
8. ساخت دو ثبت‌نام WARP، یکی برای مصرف واقعی و دیگری برای تست ایزوله؛
9. ساخت کلیدهای REALITY، رمزها، کانفیگ سرویس‌ها، قوانین فایروال و unitهای systemd؛
10. اعتبارسنجی کانفیگ‌های Xray، Hysteria و Nginx و سپس فعال‌کردن سرویس‌ها.

نصب‌کننده برای حفظ اطلاعات، روی نصب موجودی که فایل `/etc/nexagate/panel.json` دارد بازنویسی انجام نمی‌دهد.

## اتصال به CertDuo

NexaGate منطق صدور گواهی را دوباره‌نویسی نکرده است. یک commit مشخص از CertDuo دانلود می‌شود، SHA-256 آن بررسی می‌شود و پاسخ‌هایی که در نصب‌کننده انتخاب کرده‌اید به CertDuo داده می‌شود.

### حالت دامنه

CertDuo با روش HTTP-01 webroot یک گواهی معمولی Let's Encrypt می‌گیرد. مسیر فایل‌ها:

```text
/etc/letsencrypt/live/DOMAIN/fullchain.pem
/etc/letsencrypt/live/DOMAIN/privkey.pem
```

### حالت IP عمومی

CertDuo IPv4 عمومی سرور را تشخیص می‌دهد و از پروفایل گواهی کوتاه‌عمر IP در Let's Encrypt استفاده می‌کند. عمر این گواهی‌ها بسیار کمتر از گواهی دامنه است؛ بنابراین تمدید خودکار باید فعال بماند. بعد از تمدید، hook نصب‌شده Nginx را reload و Hysteria را restart می‌کند.

## مسیر پشتیبان XHTTP با TLS واقعی

هر کاربر یک پروفایل پنجم با نام **VLESS + XHTTP + TLS** دریافت می‌کند. این مسیر از گواهی واقعی CertDuo و HTTP/2 روی پورت عمومی TCP `2053` استفاده می‌کند. Nginx اتصال TLS را مدیریت می‌کند و فقط مسیر تصادفی XHTTP را با h2c محلی به Xray روی `127.0.0.1:10002` می‌فرستد. WebSocket قدیمی نیز روی همین پورت عمومی، اما با مسیر مخفی جداگانه باقی می‌ماند.

ترتیب پیشنهادی اتصال:

1. XHTTP + REALITY روی TCP `443`؛
2. XHTTP + TLS واقعی روی TCP `2053` هنگامی که REALITY اختلال دارد؛
3. Hysteria2 روی UDP `443` در شبکه‌هایی که UDP پایدار است؛
4. RAW REALITY یا WebSocket TLS برای سازگاری کلاینت و استفادهٔ اضطراری.

لینک XHTTP TLS از ALPN مبتنی بر HTTP/2 و حالت `auto` در XHTTP استفاده می‌کند. TCP داخلی همچنان از سایفون و UDP/DNS داخلی همچنان از WARP خارج می‌شود. سرور پیش از رسیدن اتصال نمی‌تواند اپراتور یا وضعیت شبکهٔ کاربر در ایران را تشخیص دهد؛ بنابراین انتخاب پروفایل در برنامهٔ کاربر انجام می‌شود.

## سازوکار سایفون

سایفون یک SOCKS5 محلی روی `127.0.0.1:1080` فراهم می‌کند و Xray و Hysteria فقط نشست‌های TCP را به آن می‌فرستند.

- برای انتخاب خودکار و اتصال مجدد هوشمند سایفون، فیلد کشور را در پنل خالی بگذارید.
- برای درخواست یک کشور ثابت، کد ISO دوحرفی مانند `DE`، `NL` یا `CA` وارد کنید.

پنل کانفیگ سایفون را دوباره می‌سازد و سرویس را کنترل‌شده راه‌اندازی مجدد می‌کند. هر پنج دقیقه سلامت خروجی SOCKS بررسی می‌شود و در صورت شکست، سایفون restart خواهد شد. کشور ثابت یک ترجیح در شبکهٔ سایفون است و موجودبودن آن تضمین نمی‌شود.

## سازوکار WARP

WARP برای UDP داخلی و DNS استفاده می‌شود و انتخاب کشور ندارد. به‌طور پیش‌فرض هر ۳۰ دقیقه بهینه‌ساز:

1. یک network namespace موقت می‌سازد؛
2. پروفایل مستقل تست WARP را داخل آن بالا می‌آورد؛
3. پینگ endpointها و پورت‌های کاندید Cloudflare را اندازه می‌گیرد؛
4. سرعت گزینه‌های دارای بهترین پینگ را آزمایش می‌کند؛
5. اگر endpoint فعلی همچنان مناسب باشد آن را حفظ می‌کند تا مسیر بی‌دلیل نوسان نکند؛
6. فقط در صورت بهترشدن محسوس، endpoint فعال را عوض می‌کند.

آخرین نتیجه در `/var/lib/nexagate/warp/status.json` ذخیره می‌شود و فضای تست بعد از هر اجرا پاک می‌شود. استفاده از WARP تابع شرایط و دسترس‌پذیری سرویس Cloudflare است.

## مسیریابی fail-closed

هم کانفیگ برنامه‌ها و هم فایروال سیستم‌عامل جداسازی را اعمال می‌کنند:

- TCP در Xray/Hysteria ← SOCKS محلی سایفون؛
- UDP در Xray/Hysteria ← رابط `warp0`؛
- DNS خروجی ← رابط `warp0`؛
- هر مسیر تطبیق‌داده‌نشده ← reject یا blackhole.

قوانین nftables فقط پاسخ ورودی‌های عمومی، ارتباط loopback با سایفون/DNS و خروجی روی WARP را برای کاربران سرویس مجاز می‌کند. باقی ترافیک متعلق به سرویس‌های Xray، Hysteria و DNS رد می‌شود. خود سایفون عمداً اجازهٔ اتصال مستقیم به اینترنت را دارد، چون مسیر خروجی TCP است.

### نمای کلی زنده

صفحهٔ Overview هر دو ثانیه اطلاعات سرور لینوکسی را تازه می‌کند و برای این کار سرویس مانیتورینگ یا کتابخانهٔ سنگین نمودار نصب نمی‌شود. اطلاعات CPU، رم، Swap، فایل‌سیستم اصلی، سوکت‌ها، پردازش پنل و آپ‌تایم از شمارنده‌های خود لینوکس در `/proc` و فایل‌سیستم خوانده می‌شوند. سرعت و مجموع آپلود/دانلود مربوط به رابطی است که مسیر پیش‌فرض شبکه را دارد؛ مقدار تجمعی از زمان بالا آمدن همان رابط محاسبه می‌شود و جای صورتحساب ترافیک شرکت میزبان را نمی‌گیرد.

پنل آدرس‌های IPv4 و IPv6 غیرمحلی رابطی را نمایش می‌دهد که مسیر پیش‌فرض شبکه روی آن قرار دارد. این آدرس‌ها به‌صورت پیش‌فرض محو هستند؛ با دکمهٔ چشم نمایش داده می‌شوند و با کلیک دوباره پنهان می‌گردند. این قابلیت برای حفظ حریم هنگام اسکرین‌شات یا اشتراک صفحه است، نه یک مرز امنیتی مستقل؛ API آمار فقط در اختیار مدیر واردشده به پنل قرار دارد.

حالت فارسی و انگلیسی کاملاً از هم جدا هستند. دکمهٔ تغییر زبان، انتخاب مدیر را در کوکی هم‌سایت ذخیره می‌کند، جهت صفحه را میان راست‌به‌چپ و چپ‌به‌راست تغییر می‌دهد و کاربر را در همان صفحه نگه می‌دارد. برچسب‌های دو زبان در یک نما با هم ترکیب نمی‌شوند؛ فقط نام فنی پروتکل‌ها و محصولات مانند TCP، Hysteria2، Psiphon و WARP بدون ترجمه باقی می‌مانند.

### به‌روزرسانی یک‌کلیکی پنل

در Overview روی **بررسی و آپدیت** بزنید. پردازش وب فقط یک درخواست محدود می‌نویسد و یک سرویس systemd جداگانه و متعلق به root مراحل نیازمند دسترسی بالا را انجام می‌دهد:

1. آخرین انتشار را فقط از مخزن ثابت `MehrooExplains/nexagate` می‌خواند؛
2. آرشیو Linux amd64 و فایل `SHA256SUMS` را از همان tag دانلود می‌کند؛
3. tag، آدرس دانلود، مسیرهای داخل آرشیو، checksum، نسخهٔ داخل آرشیو و نسخه‌ای که باینری گزارش می‌کند را تطبیق می‌دهد؛
4. باینری قبلی پنل را نگه می‌دارد، نسخهٔ جدید را اتمیک نصب می‌کند و پنل را restart می‌کند؛
5. مسیر `/healthz` را آزمایش می‌کند و اگر اجرا یا تست سلامت شکست بخورد، خودکار نسخهٔ قبلی را برمی‌گرداند.

این دکمه فایل اجرایی NexaGate را به‌روزرسانی می‌کند. باینری جدید در نخستین اجرا، مقدارهای جدید و خالی کانفیگ را به‌صورت امن تکمیل می‌کند، فایل را اتمیک ذخیره می‌کند، کانفیگ سرویس‌ها را دوباره می‌سازد و آن را از مسیر موجود اعتبارسنجی و اعمال می‌کند. اگر یک انتشار آینده صراحتاً بسته‌های سیستم‌عامل یا سیاست‌های systemd/شبکه را تغییر دهد، ممکن است اجرای روش مهاجرت نوشته‌شده در همان انتشار لازم باشد. SHA-256 سلامت فایل و اختلاف دانلود را کنترل می‌کند؛ اعتماد نهایی همچنان به مخزن و حساب انتشار GitHub وابسته است. نسخه‌ها با `.github/workflows/release.yml` ساخته می‌شوند و دکمه در buildهای توسعه عمداً غیرفعال است.

دستورهای کاربردی:

```bash
sudo nexagate doctor
sudo systemctl status nexagate-panel nexagate-xray nexagate-hysteria nexagate-psiphon
sudo journalctl -u nexagate-psiphon -u nexagate-hysteria -n 100 --no-pager
sudo systemctl start nexagate-warp-optimize.service
cat /var/lib/nexagate/warp/status.json
```

مسیرهای مهم:

| مسیر | توضیح |
|---|---|
| `/etc/nexagate/panel.json` | کانفیگ پنل و مسیرها؛ شامل اطلاعات محرمانه |
| `/var/lib/nexagate/users.json` | دیتابیس کاربرها و اطلاعات اتصال |
| `/etc/nexagate/generated/` | کانفیگ‌های تولیدشدهٔ Xray، Hysteria، Psiphon و Nginx |
| `/etc/wireguard/warp0.conf` | پروفایل فعال WARP |
| `/etc/nexagate/warp-probe.conf` | پروفایل مستقل بهینه‌ساز |
| `/var/lib/nexagate/warp/status.json` | نتیجهٔ آخر تست WARP |
| `/var/lib/nexagate/update-status.json` | آخرین وضعیت آپدیت که در Overview نمایش داده می‌شود |

از پنج مسیر محرمانهٔ اول به‌شکل امن نسخهٔ پشتیبان بگیرید و هرگز محتوای آنها را در Issue عمومی قرار ندهید.

## رفع اشکال

- ابتدا `sudo nexagate doctor` را اجرا کنید.
- فایروال شرکت میزبان را در کنار فایروال خود سرور بررسی کنید.
- برای دامنه مطمئن شوید رکورد `A` مستقیم به سرور resolve می‌شود.
- دسترسی TCP پورت `80` را برای تمدید گواهی حفظ کنید.
- اگر UDP یا DNS مشکل دارد، وضعیت `wg-quick@warp0` را بررسی کنید.
- اگر TCP مشکل دارد، پورت محلی `127.0.0.1:1080` و log سایفون را بررسی کنید.
- اگر فقط یکی از پروفایل‌ها خراب است، ابتدا سرویس Xray یا Hysteria مربوط به همان ورودی را بررسی کنید.

## نکات امنیتی و محدودیت‌ها

- هستهٔ پنل فقط روی loopback گوش می‌دهد و از HTTPS پورت `8443` منتشر می‌شود.
- رمز مدیر با PBKDF2-HMAC-SHA-256 و salt تصادفی ذخیره می‌شود؛ session امضاشده، Secure، HttpOnly و SameSite Strict است.
- پنل محدودسازی تلاش ورود، CSRF، هدرهای امنیتی و نوشتن اتمیک فایل‌ها را اعمال می‌کند.
- هر سرویس کاربر محدود جداگانه و sandbox سخت‌گیرانهٔ systemd دارد.
- لینک کانفیگ شامل اطلاعات اتصال است؛ دارندهٔ لینک تا زمان غیرفعال‌شدن، حذف یا انقضای کاربر می‌تواند متصل شود.
- مسیرهای Psiphon و WARP به شبکه‌ها و سیاست‌های سرویس‌دهندگان ثالث وابسته‌اند.
- WARP برای انتخاب کشور استفاده نمی‌شود و موجودبودن کشور ثابت در Psiphon ممکن است تغییر کند.
- پروژه ناشناس‌بودن، دسترسی بدون محدودیت یا سازگاری با تمام ISPها و DPIها را تضمین نمی‌کند.
