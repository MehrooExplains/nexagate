# NexaGate

Панель управления `v0.3.0` с маршрутами Hysteria2, VLESS XHTTP Reality, VLESS XHTTP TLS, RAW Reality и WebSocket TLS.

## Быстрый старт

Установка выполняет проверку и установку зависимостей автоматически:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/MehrooExplains/nexagate/main/install.sh)
```

После установки откройте HTTPS-панель и используйте ссылки или QR-коды пользователей. TCP-трафик направляется через Psiphon, UDP — через WARP. Существующие конфигурации обновляются автоматически и безопасно.

Полная документация доступна на [английском](README.md) и [фарси](README.fa.md).

## Подробное описание

NexaGate намеренно разделяет выходящий трафик: TCP направляется в Psiphon, а UDP и DNS — в Cloudflare WARP. Fail-closed firewall не позволяет Xray, Hysteria и DNS-relay незаметно использовать обычный интернет-маршрут сервера при сбое туннеля.

> Версия: `0.3.0`. Сначала проверяйте проект на новом сервере, который можно восстановить. Ни один протокол не гарантирует доступ при всех видах сетевой фильтрации.

### Архитектура и порты

```text
Клиенты
  ├─ UDP/443  ─ Hysteria2
  ├─ TCP/443  ─ VLESS + XHTTP + REALITY
  ├─ TCP/8444 ─ VLESS + RAW + REALITY + Vision
  └─ TCP/2053 ─ Nginx TLS/HTTP2
                    ├─ VLESS + XHTTP + TLS
                    └─ VLESS + WebSocket + TLS

Управление: TCP/8443 → Nginx HTTPS → панель на 127.0.0.1:9080
```

| Порт | Назначение |
|---|---|
| UDP `443` | Hysteria2 + Salamander |
| TCP `443` | VLESS XHTTP + REALITY |
| TCP `8444` | VLESS RAW + REALITY + Vision |
| TCP `2053` | VLESS XHTTP TLS и WebSocket TLS |
| TCP `8443` | HTTPS-панель |
| TCP `80` | HTTP-01 для сертификатов |

Одновременное использование TCP и UDP на `443` допустимо: это разные транспорты. Откройте TCP `80,443,2053,8443,8444` и UDP `443` в firewall сервера и в security group провайдера.

### Установка

Нужны новый systemd Linux-сервер, `amd64`/`x86_64`, публичный IPv4 и root/`sudo`. Поддерживаются `apt`, `dnf` и `yum`; Debian/Ubuntu проверяются чаще всего. Установщик повышает права при необходимости, проверяет зависимости и ставит только отсутствующие пакеты.

Он спрашивает только тип сертификата, e-mail Let's Encrypt и имя домена в режиме домена. Надёжный случайный пароль администратора создаётся автоматически, один раз выводится по завершении и сохраняется в root-only файле `/root/nexagate-initial-credentials.txt`. После входа смените пароль в **Panel Settings** и удалите этот файл.

### Сканер цели REALITY

Откройте **Panel Settings → REALITY Target Scanner**. Пустой ввод проверяет встроенные домены; также можно проверить домен либо публичный IPv4 CIDR `/28` или меньше (не более 16 адресов). Сканер измеряет TLS, ALPN, сертификат, предпочтение X25519 и задержку непосредственно с сервера. Частные и специальные сети исключены.

IP/CIDR-результаты являются информационными. Кнопка **Use** появляется только для проверенного домена, поскольку REALITY нужен подходящий SNI hostname. Результат `feasible` показывает совместимость TLS, но не является гарантией доступности во всех сетях.

### Панель и безопасность

- Панель показывает CPU, RAM, swap, диск, скорость/объём сети, сокеты, uptime и собственное потребление ресурсов; IP сервера скрыт до нажатия на значок глаза.
- Доступны пользователи, ссылки подписки, QR-коды, автоматический Psiphon/WARP, однонажатное обновление с checksum и rollback, а также сертификаты через [CertDuo](https://github.com/MehrooExplains/certduo).
- Пароли хешируются PBKDF2-HMAC-SHA-256 с солью; сессии Secure, HTTP-only и SameSite strict. Есть CSRF-защита и ограничение попыток входа.
- Не публикуйте ссылки подключения: они содержат учётные данные. При утечке отключите или удалите пользователя.

```bash
sudo nexagate doctor
sudo nexagate backup create --encrypt --password
sudo nexagate backup list
```
